# Accessibility audit, October 2026

Report only: no app code was changed. Method: `@axe-core/playwright` (axe-core rules for WCAG 2.0 / 2.1 / 2.2 A and AA plus best-practice) on the mock backend, and a keyboard-only pass driven by Playwright. Both live in `apps/desktop/e2e/a11y.spec.ts`; run with `cd apps/desktop && npx playwright test e2e/a11y.spec.ts`.

Baseline: `origin/main` at 010215e, Chromium (Playwright build), dark theme, 1440x900, `prefers-reduced-motion: reduce` emulated so fade-ins do not distort contrast numbers.

## How the spec treats known failures

- Axe tests: each screen lists the rules it is allowed to report, each tagged with a finding id. A rule that is not on the list fails the test (regression guard). The listed ones show up as `known-issue` annotations in the report.
- Keyboard tests: behaviour that works today is asserted normally. Behaviour that is broken today is `test.fail()` with the finding id in the reason, so the test turns red ("expected to fail but passed") when the fix lands, and the marker has to be removed then.
- Result of the last run: 35 passed (21 plain, 14 expected failures). Every expected failure maps to a finding below.

## Status

- A11Y-06 partly fixed (`ui/ContextMenu` and the message menu in `chat/MessageMenu.tsx`): Shift+F10 and the Menu key now open the menu of the focused control on every platform (`ContextMenuHost` dispatches the `contextmenu` event itself: macOS and WKWebView never produce it natively), and Tab closes an open menu instead of walking away behind it. Still open: moving DOM focus into the menu / `aria-activedescendant` on the rows.
- Quality pass (worktree-quality):
  - A11Y-03 fixed: the @everyone button sits in its own `role="listitem"`.
  - A11Y-08 fixed: the message scroller shows the 2px ring on `:focus-visible` (it overrides Virtuoso's inline `outline:none`), and the composer box border brightens while the textarea has focus. A full ring while typing was left out to match Discord's caret-only composer (parity note below).
  - A11Y-09 fixed: the user-panel chevrons are 24px wide, and the channel action buttons are 24x24 with the same 8px between icons as before.
  - A11Y-10 fixed: the scroller is named "Messages in #channel", and a new message from someone else in the open channel is announced through the app's one polite live region (`ui/announce.tsx`): "Name: text" (first 200 characters). `role="log"` was not used because Virtuoso mounts and unmounts rows while scrolling, and a log would read them out again.
  - New scans: the voice call view and the create-server modal. They found A11Y-21 and A11Y-22 (both in `src/voice/`, open; vokko-call-perf owns that code this round).
  - Accessibility-tree snapshots of guild chat, voice call, DM, quick switcher and user settings are attached to the run (`VOKKO_A11Y_SNAPSHOTS=<dir>` also writes them out as YAML). There is an NVDA checklist for a manual pass in `docs/audits/nvda-checklist.md`.
  - Still open: A11Y-07 (contrast, a parity decision; High Contrast mode exists), A11Y-21/22, and the moderate and minor findings.

## Not covered / limits

- No screen reader was run (NVDA, VoiceOver, Orca). "Announced" claims are derived from the accessibility tree and ARIA markup only.
- Nothing visual was judged beyond what axe computes. The sandbox cannot check how focus rings, hover states or the overlays look.
- Only the dark theme was scanned. Light, midnight and onyx token sets (`styles/tokens.css`) and the Appearance theme picker still need a contrast pass.
- Not tested: 200% / 400% zoom and reflow (1.4.4, 1.4.10), text spacing (1.4.12), touch, the Tauri webview (WebKitGTK / WebView2 / WKWebView can differ in focus behaviour), voice/video UI (not built), the composer's "type anywhere to focus" shortcut, the remaining settings pages, and the pages other workers still change.

## What works

- Focus rings: one 2px `--focus-ring` outline (`styles/base.css:87`) on every link and button reached with the keyboard (rail, channel list, header, composer buttons, member rows, user panel).
- `Modal` and the settings overlays trap Tab, set `aria-modal`, focus the first control and return focus to the opener on Esc (opener still in the DOM).
- Esc closes only the top layer (`ui/layers.ts`), including a dialog opened over a menu.
- Ctrl+K opens and toggles the quick switcher with the input focused; arrows select, Enter navigates. Alt+Up / Alt+Down switch text channels and keep focus in the composer. Up in an empty composer edits the last own message.
- Labelled landmarks (`nav` "Servers sidebar", `main`, `aside` "Members", user panel region), status dots have text alternatives, `prefers-reduced-motion` is honoured (`styles/base.css:196`), the Roles list and category toggles expose list / `aria-expanded` state.

Severity: **Critical** blocks a task for keyboard or screen-reader users; **Serious** makes it hard or unreliable; **Moderate** degrades it; **Minor** polish. "axe" gives axe's own impact where it differs.
